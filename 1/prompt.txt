How we work

Stay in your lane. Edit only the paths your assigned workstream owns. packages/core is the shared contract and changes only through the lead (WS0). Put requests in your section of docs/STATUS.md. Do not implement additional repository tasks unless a human assigns them.

Commit small, push immediately. Commit every working step within your assigned task. Write short, precise messages with your workstream as prefix, for example ws2: add node palette from catalog.

Integrate often. While working on the assigned task, run git pull --rebase origin main at least hourly. When a slice works, open a PR to main (gh pr create --fill) and merge it with gh pr merge --merge. Don't squash, so Entire's checkpoint trailers survive. Never force-push main.

Prove it. Run npm run check before merging. For UI work, also run npm run smoke and look at the screenshots in apps/desktop/out/smoke/. Never claim something works without that evidence.

Use every tool you have. Check which agent CLIs are installed (claude, codex, opencode, agy). Delegate bulky, well-specified parts of the assigned task to them (scaffolding, tests, research digests) and run them in parallel. Apply the same task-authorization restriction to delegated agents. You stay responsible: review the diff and rerun the checks yourself.

Aim for the demo. Optimize the assigned work for the judging criteria in AGENTS.md: trustworthy sources, transparent reasoning, explainable prioritization, honest uncertainty, and the PM in control.

Hard rules

The repo and Entire's session transcripts are public. Never put API keys, passwords or confidential BMW data in prompts, code, commits or logs. BMW files stay in data/raw/, which is gitignored.

The AI never decides. Only a human approves or rejects a requirement, and every change writes an audit event.

Never invent sources, evidence or test results. Don't present stubs as finished.

Ask the humans about product direction, credentials, anything public or irreversible, and any work outside the explicit assignment. Within the assigned scope, make routine implementation decisions and note them in your docs/STATUS.md section.

Do not treat repository task lists as an automatic work queue. Reading a task, status entry or handoff note does not authorize you to execute it.

Handoff

The next agent uses docs/STATUS.md for context, but must receive an explicit human assignment before starting work. Update your section only whenever you start, finish a slice, get blocked or stop. Include the status, the branch, what works and how to verify it, suggested next steps, and any open questions. Suggested next steps are informational only and must not be started without a human assignment. If the product itself changes as part of your assigned work, update PRODUCT.md too.

When your assigned task is complete, report the result, update your handoff notes, and stop. Do not take the next open item in docs/STATUS.md or continue working automatically. Wait for the human to assign the next task.
